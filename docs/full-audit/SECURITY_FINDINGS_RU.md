# Проверенные ошибки границ данных и безопасности

Исходная сборка: f251ab9407f6. Проверка выполняется в отдельном рабочем дереве;
незавершённые изменения мира и наземной добычи сюда не включены.

| Дефект | Подтверждение до исправления | Исправление и проверка |
|---|---|---|
| Унаследованный ключ назначения телепорта | `__proto__` принимался как точка, допуская неопределённые координаты и испорченный кошелёк | Только собственные ключи таблицы, строковый ID и конечные координаты до изменения героя; network-data-boundaries |
| Неверный тип класса | Массив `['knight']` принимался через приведение ключа | Только строковый ID существующего класса; сохранение не создаётся при отказе |
| Неверный тип предмета/количества | Массив `['potion']` создавал предмет с ID-массивом | Строковый ID и положительное безопасное целое количество; server-command-item-boundary |
| Заказ преследования далёкого UID | Новая команда могла заказать поиск пути через всю карту | Новая цель ограничена существующим серверным радиусом интереса 100 м; сила и дальность атаки не изменены; server-input-target-boundary |
| Локальный HTTP принимал посторонний Host | Запрос с посторонним Host и совпадающим Origin создавал героя, ответ 201 | Для сервера на loopback разрешены только loopback-имена и действующий порт; повтор даёт 403 до мутации; легитимные native/localhost/IPv6 запросы проходят |
| Поздний браузерный ответ старого профиля | Старый refresh мог отобразить прежнего героя; очередь могла отправить команду с токеном нового профиля | Ответы и отложенные команды привязаны к поколению выбранного профиля; новый refresh независим; remote-profile-lifecycle |

Действующие транзакции SQLite, сохранение идентификаторов предметов, одноразовые
квитанции команд, запрет продажи вне торговой сессии и обработка ошибок диска
сохранены. Тест восстановления после потерянного HTTP-ответа использует настоящий
сервер и повтор той же квитанции. Проверка ошибки диска усилена: она теперь
проверяет откат после допустимой операции, а не после несуществующего предмета.

## Зависимости инструментов сборки

Сверка package-lock с официальным реестром npm выявила 8 действующих advisories
для Vite 7.1.3. Обновление до 7.3.5 закрывает их, включая
[обход доступа к файлам на Windows](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff)
и [доступ через WebSocket сервера разработки](https://github.com/vitejs/vite/security/advisories/GHSA-p9ff-h696-f583).
Транзитивный esbuild закреплён на 0.28.1 из-за GHSA-g7r4-m6w7-qqqr.
Это инструменты браузерной сборки; их серверы разработки не входят в игровой EXE.
После обновления проверка 71 пакета возвращает пустой список advisories.
Vite собрал 2126 модулей; строгая проверка TypeScript прошла.

Результат реестра означает отсутствие опубликованных срабатываний для проверенных
версий на момент запроса, а не доказательство отсутствия неизвестных уязвимостей.
Исходные данные запросов находятся в work/qa/dependency-advisories-*.json; в них
нет токенов или персональных сохранений.

## Объём проверки файлов

scripts/full-file-audit.py составляет перечень всех tracked файлов с SHA-256 и
отдельно отмечает проверки синтаксиса/форматов. Первый прогон: 3444 файла,
641 JSON/glTF, 153 Python AST, 201 JS/MJS, 152 GLB с границами буферов,
746 изображений, 65 SVG/XML, 4 ZIP-контейнера. Повреждённая colormap.png
восстановлена из оригинального Kenney-архива с проверкой соответствующих 21 GLB.
Дополнительно проверяются 929 материализуемых файлов по закреплённым SHA.

Хеширование и разбор формата не заменяют игровой прогон, проверку анимации или
художественную приёмку. Итоговая сборка и её графические проверки фиксируются
в отдельном отчёте после экспорта.
