# Исправление проверки исторического SHA на Linux

Source audit коммита `bbe0e344a061` завершился с одним сбоем:
[run 34721538091, job 103628232579](https://github.com/Pakka19941311/Pakka/actions/runs/34721538091/job/103628232579).
Материализация и подготовка прошли; dependency audit прошёл; Node выполнил
732 теста: 731 PASS, 1 FAIL, без пропусков. Vite не запускался после ошибки теста.

Единственный FAIL: историческая подпись
`godot-pc/world-final/castle/courtyard.json` в `world-expansion-v3.test.mjs`.
Исторический файл был подписан на Windows с CRLF. Git хранит его с LF,
и Ubuntu получает именно эту версию. Прежний helper умел сравнивать raw и LF,
поэтому проверял LF-подпись на CRLF-checkout, но не обратный случай.

Доказательство по неизменному blob коммита `bbe0e344a061`:

| Представление | SHA256 |
|---|---|
| Git blob, LF | `aa325c26357b6db1accbf207e3bc2002909b7d1fe8e2712f4860876e05b33348` |
| Тот же blob с CRLF, совпадает с исторической подписью | `0e2770b57522471bfe2828739735ae4beecb7678c14c38116b9e6877aa91fed6` |

Локальный исходник побайтово совпадает со вторым представлением. Между ними
меняются только переводы строк; содержимое JSON не меняется. Исправлен только
тестовый helper: допустимы raw, LF и CRLF-представления той же строки. Значения,
отступы, порядок полей, наличие завершающего перевода строки и записанный SHA
не нормализуются и не обновляются.

Регрессионные тесты проверяют обе стороны LF/CRLF и отказ при изменении значения,
отступа, порядка полей и удалении последнего перевода строки. Дополнительно
проверена LF-копия настоящего Git blob против неизменной исторической подписи.
Игровые файлы, геометрия, отчёты исторической приёмки и EXE не изменены.
Полная suite будет повторена в CI; локально выполнена только узкая проверка.
