# Проверка native ввода и интерфейса, 12 сентября 2026

База аудита: `f251ab9407f6`, исправления в отдельной рабочей копии от `6279`. Native исходники этих двух ревизий до данного изменения совпадали. Личные сохранения не открывались. Этот отчёт подтверждает ограниченный клиентский блок; он не заменяет полный графический прогон собранного пакета и не доказывает единственную причину всех сообщений о зависании.

## Исправленные причины

1. **Устаревшие направления задерживали отпускание движения.** `player_input.gd:23,78–86` выдаёт до 60 изменённых направлений/с при вращении камеры. Исторический `input_transport.gd:23–27,44–58` добавлял каждое в неограниченную FIFO, обслуживаемую одним последовательным HTTP worker. Измеренные другим блоком аудита ответы 43–195 мс дают лишь 5–23 запроса/с. При таком режиме задолженность направлений растёт; очередной stop ждёт старые повороты. Теперь `input_transport.gd:23` под тем же mutex оставляет последнее **неотправленное** направление внутри непрерывной группы с одинаковыми session/generation. Уже отправленное и каждое jump/attack/cancel/destination остаются барьерами. Замена использует существующий semaphore permit. `network.gd:357` удаляет только соответствующий неотправленный bookkeeping; предсказание каждого локального ввода и история движения сохраняются. Сервер уже допускает пропуски sequence и отвергает повторные/старые номера (`world-simulation.ts`, обработчик input).

2. **Поздний ответ перехватывал диалог.** Покупка книги и старая награда после `await command` безусловно заново вызывали catalogue/quest_menu. Ответ после Esc мог снова открыть модальное окно и забрать WASD через `main.text_focused()`. У продажи, крафта и квестовых окон тот же класс гонки: старый callback обращался к новому box либо ещё не удалённому `queue_free` окну. `dialog_lease.gd` проверяет исходное живое окно, сессию, ID и поколение героя. Обновляется только оно. Новый квестовый/крафтовый open начинает собственный `local_busy`; старый callback не снимает занятость новой операции.

3. **Поздний TP закрывал произвольное новое меню.** В `main.gd` callback успешного TP теперь может закрыть только своё окно той же сессии/героя. Для этого конкретного успешного действия разрешено новое поколение; исключение не распространяется на другой профиль или заменившее меню.

4. **Смена профиля оставляла старый склад и targeting.** `main.switch_profile()` теперь закрывает диалог, склад и tooltip, очищает slot/signature склада, отменяет book targeting и старый таймер loot popup. Old trade-close tokens очищаются. `has_item_version()` при пустом герое безопасно возвращает false. `trade_session.open()` проверяет сессию после await прежде, чем использовать захваченный receipt: старая операция не может открыть либо закрыть token нового профиля.

## Проверка

Финальный `work/qa/native-input-backpressure-05`: **56/56 native условий**, 3/3 условий HTTP driver; process exit 0, чистый журнал ошибок, 5,235 с. Receiver синтетический localhost, HTTP worker, Network, PlayerInput, CameraController и PlayerMovement настоящие. Ответ input намеренно задержан на 120 мс.

- 60 последовательных семплов камеры с удержанием W; непосредственное локальное отпускание W/ПКМ, затем фактический stop ACK **186 мс**.
- Истинная очередь **неотправленных** направлений измерена под mutex: максимум **1**, плюс один возможный HTTP in flight. Максимум network bookkeeping в финальном запуске 2; в запуске 04 был 3, поскольку уже завершённый HTTP ожидал deferred callback. Это другой показатель, он не выдаётся за три неотправленные команды.
- 93 устаревших направления заменены: 51 в steering и 42 между action barriers. Jump, attack, destination и cancel исполнились в исходном порядке; последний neutral сохранился.
- TP вызван обычным `Network.command` с изолированным journal и синтетическим ответом generation 2. Предсказание и старый worker сброшены; запоздалые generation/session ответы, повторный callback и transport error не очищают новый ввод.
- Настоящие book/shop/sale callbacks с задержанным завершением не переоткрывают закрытые окна, не заменяют новое меню, не переходят между поколениями/профилями. Проверены late craft/starter/progression replies, trade receipt isolation, удаление профильно зависимых окон и пустой герой.
- Существующие проверки prediction/ACK и SSE повторены: UTF-8 на границе байта, несколько packets с сохранением всех событий, частичный хвост, version incompatibility, late session/receipt и сохранение старого pending journal.

В headless нет достоверной проверки OS cursor. Для steering вызываются production orbit и update_pose; lifecycle ПКМ проверен, но фактическое захватывание/возврат указателя остаётся для графического QA. Импортный cache шести неизменённых SVG использован после сравнения исходного текста с нормализацией CRLF, без изменения source assets.

Предыдущие запуски 01/02 сохранены как ошибки тестовой подготовки (невалидный Windows filename синтетического ID, отсутствующий import cache и неполная инициализация камеры). 03 — промежуточные 44/44; 04 — 55/56 с неверным смешением bookkeeping и unsent очереди. История не переписана.

Повтор: `node scripts/native-input-backpressure-qa.mjs <python> <Godot-console.exe> <new-output-dir>`. Driver использует только `scripts/godot_run_checked.py`, отдельные APPDATA/LOCALAPPDATA и синтетический journal. Файлы `native-input-result.json` и `native-input-sources.json` содержат компактный результат и fingerprints проверенных источников.

## Охват чтения и границы

Рассмотрены production пути `network`, `input_transport`, `player_input`, `player_movement`, `camera_controller`, `snapshot_timeline`, `main`, `targeting`, `npc_interaction`; окна и действия `book_ui`, `trade_session`, `sale_dialog`, `sale_drop`, `crafting_dialog`, `craft_slot`, `starter_quests`, `progression_quests`, `item_slot`, `quick_slot`, `reference_hud`, `interface_polish`, `drag_preview`; вспомогательные `reference_icons`, `titan_theme`, `minimap`, `reference_minimap`. Для крупных layout файлов проверялись исполняемые обработчики/async/I/O/циклы и связи, а не художественная правильность всех чисел размещения. QA-only сценарии не считаются игровыми функциями.

Журнал предметных действий по-прежнему сохраняется до POST, retry сохраняет command ID. Предметные UID/count/plus и доступ к продаже по-прежнему проверяет сервер. Данный блок не меняет валюту, дроп, damage, скорость, частоту autoattack, prediction physics или права торговли.

Остаются отдельные проверки полного мира: реальное визуальное движение после всех переходов, correction/тайминг на графическом клиенте, стабильность SSE под загрузкой, CPU/GPU загрузка новых актёров и профиль полного пакета. Синхронный make_actor в snapshot и пересоздание preview кольца area-book переданы владельцу render-аудита; здесь их стоимость не измерялась. Общий лимит намеренно спамящих дискретных действий не вводился: они не выбрасываются ради скорости stop. Защиту/лимиты серверных запросов проверяет отдельный блок. Бесплатное восстановление HP, новые предметы и population activation в этот hotfix не входят.
