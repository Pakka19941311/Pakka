# Графический сценарий проверки стабильности

Это QA-инструмент. Он не изменяет игровые механики или ресурсы. Полный графический результат пока не получен; Node проверка размещения тестгероя 1/1 PASS, синтаксис Node driver проверен. Проверка Godot `audit-stability-parse-01` завершилась с кодом 0 за 1,047 с, журнал без ошибок и предупреждений. Графический запуск фиксируется отдельными артефактами и не подменяется успешным разбором скрипта.

`node scripts/native-stability-qa.mjs <Godot-console.exe либо packaged EXE> <новая папка> [--package=<папка пакета>] [--saved-copy=<закрытая проверенная копия world.sqlite>] [--budget=210] [--qa-user-root=<изолированный профиль>] [--qa-graphics=low]`

Python берётся из `PYTHON`. Движок запускается только через checked wrapper. Для работы на сохранённом мире передаётся **готовая копия**: driver копирует её ещё раз в `private-save/world.sqlite`, сверяет SHA до/после и не открывает исходную копию на запись. Наличие непустого WAL запрещено. Без параметра создаётся чистый мир. Папка QA должна быть новой. Bootstrap с токеном и SQLite находятся только в отдельной папке запуска и не предназначены для публикации/коммита.

В настоящем сервере создаётся отдельный тестгерой knight40, с 10000 золота и полным HP/MP один раз в начале. После переходов HP, деньги, инвентарь, монстры и игровые часы не подменяются. При нехватке ресурсов или смерти сценарий честно проваливается. Существующая популяция и её таймеры загружаются обычным серверным путём, затем тикают реально.

Сценарий вызывает четыре доступных TP через кнопку текущего NPC-диалога: Астерхолд, Гринфолл, Чёрный лес, вход в шахту. Fixture только ставит тестгероя рядом с телепортером перед каждым TP. Затем обычный F вводит в mine и great_cave; выход достигается обычным движением и F. Fixture переход не совершает. `native-stability-fixture.test.mjs` проверяет свободные/доступные подходы в актуальном мире, координатный знак, неизменность полной популяции, часов и ресурсов.

После каждого TP/входа проверяются: свободная точка появления, W/A/S/D через viewport input, движение W, подтверждённая остановка и неподвижный интервал, R и его отключение, настоящая проекция клика/достижение точки, окно инвентаря/Esc, системное меню/Esc и здоровье/HUD. После каждого surface TP наблюдение продолжается минимум11 секунд от появления: проверяются именно координаты назначения и отсутствие позднего возврата через карту, а не только изменение generation. Сохраняются кадры шести мест и двух выходов. Неподвижное финальное наблюдение длится до20 секунд.

Лимит игровых проверок — 120–240 секунд (по умолчанию210), с сохранением частичного QA при исчерпании. Wrapper дополнительно ограничивает загрузку и весь процесс (`budget+150` секунд); если сам движок перестал исполнять GDScript, wrapper завершит принадлежащий этому запуску процесс и сохранит диагностику. `stability-progress.json` обновляется раз в2 секунды, поэтому последний достигнутый шаг остаётся и при полном зависании.

`stability.json` и `stability-summary.json` содержат проверки, средний наблюдаемый FPS, p50/p95/p99/max времени кадров, max паузы во время игры, возраст SSE, число disconnect, очереди и наибольший показанный correction offset. `stability-trace.json` содержит отдельные wall, local physics, remote interpolation, server clocks, координаты motor/render и offset. В нём нет имён, ID персонажей, инвентаря и токенов. Не используется ошибочная оценка шага локального героя по часам remote interpolation. Correction offset — наблюдаемая величина; он не выдаётся за точную сумму применённых коррекций.

Грубый freeze gate ловит паузу игрового кадра от2 секунд; это **не** обещание хорошей плавности ниже этого порога. Реальные кадры, p95/p99 и коррекции требуют просмотра. Loading отдельно помечен в trace; loading/max frame также публикуется. Финальный PASS требует всех маршрутов, отсутствия disconnect и завершения в бюджете. Полный пакет и исходная графическая версия — разные результаты, не подменяют друг друга.
