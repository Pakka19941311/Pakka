# Сохранение уровня и остановка персонажа

Продолжение `work/character-art-v3` от `9f2e84a35d351b8e4a218542770ebc36bdd7750c`. Исправляются замечания к Windows ZIP `30571757e06e`; основные ветки не меняются.

## Подтверждённые причины

В записи «Запись 2026-09-10 120517.mp4» (37,933 с, 30 кадров/с, 3822×2140) нижний HUD уже в начале показывает уровень 1 при подписи «10» над героем. После первого убийства, к 16,5 с, HUD показывает уровень 7, максимальное HP меняется с 1173 на 1040, подпись остаётся прежней. Это разные проявления одной ошибки данных плюс устаревшая подпись. Просмотрены последовательности движения, остановок и боя; около 0,5–1,1 и 2,0–2,5 с отдельно рассмотрены последовательные кадры остановок. Оригинальная пользовательская запись и личные сохранения в Git не публикуются.

`relocate()` копировал результат `findNearestFree()` целиком в героя. Если точка была свободна, функция возвращала исходный объект с полями `level` и `cost`. Требование портала `level:1` заменяло настоящий уровень. Остаток XP сохранялся, поэтому следующее убийство повторно проходило дешёвые пороги младших уровней. Исправлены обе границы: геометрическая функция возвращает только x/z, телепорт явно присваивает только координаты. Подпись существующего актёра обновляется из каждого представленного снимка.

Для скольжения прежние проверки длинных прямых пробежек были недостаточны. Новый сценарий с короткими движениями, отпусканием WASD и поворотами камеры воспроизвёл смещение до **0,400478 м** после остановки. Обнаружены:

1. Персонаж уже переходил в idle, а интерполяция ещё доигрывала последний физический шаг. Теперь граница остановки закрывает этот остаток.
2. Каждый образец направления открывал новое TCP-соединение. При поворотах камера создавала очередь, и сервер получал отпускание позже. Рабочее соединение теперь используется повторно; после простоя оно заблаговременно обновляется, чтобы закрытие сервером не теряло следующую команду. Порядок команд и защита поколения сохраняются.
3. Темп шага рассчитывался по физическому мотору, хотя отображаемое смещение могло отличаться из-за сетевой коррекции. Походка теперь получает фактически отображённое перемещение. Телепорт отдельно сбрасывает исходную позицию для измерения, поэтому не превращается в огромный шаг анимации.

Серверные скорость, урон, время автоатаки, пять принятых ударов, исходный риг и принятые клипы не менялись. Не увеличивался допустимый остаток сетевой коррекции и не отключалась серверная проверка положения.

## Уже повреждённые сохранения

При запуске локальной Windows-сборки проверяется сохранённый профиль предыдущего запуска. Если его идентификатор, класс и более высокий уровень подтверждают потерю, а в герое осталось ошибочно скопированное поле стоимости портала, можно восстановить подтверждённый минимум прогресса. Возвращается также XP, который последующие убийства успели потратить на ошибочные младшие пороги. Сначала выполняется SQLite online backup с проверкой всех таблиц и состояния. Предметы, золото, UID и выполненные задания не откатываются. Восстановление записывается в журнал мира и не повторяется при следующем запуске.

Предыдущий локальный профиль не является полной историей прокачки. При недостаточных данных уровень не угадывается; более поздний потерянный прогресс может потребовать резервной копии. Этот механизм не доступен через сетевой API. Личная база на компьютере была недоступна для чтения из рабочей среды даже после выдачи разрешения; фактическое восстановление личного героя не заявляется. Проверен полный путь на специально повреждённой отдельной базе через поставляемый запускатель.

- Проверки предсказания движения: остановка при задержке до 800 мс, старые и повторные пакеты, препятствия, начало движения после остановки, телепорт и смена поколения; отдельная проверка движения с крупной коррекцией.
- Графический сценарий клиента: 19 проверок, включая реальный переход Гринфолл → Астерхолд → Гринфолл, уровень/XP, подпись, короткие пробежки и девять остановок. Все девять остановок: **0 м** смещения. Повтор при ограничении 15 FPS также прошёл. Запрошенный размер окна соответствует записи; логический UI viewport остаётся 1600×900 и масштабируется.
- Графическая регрессия: 18 проверок склада, двух длинных пробежек, автоатаки всеми пятью ударами, отсутствия стрельбы, шести книг рыцаря и положения добычи. При 12 FPS и искусственной паузе 800 мс: оба обратных смещения **0 м**, обе остановки **0 м**. Проверка отвергает неожиданный разрыв локального соединения.
- Windows/GPU: RTX 3070 Laptop. Локальная среда печатает известную ошибку чтения корневых сертификатов; она отдельно учитывается в проверке редакторного бинарника. Полный выпуск обязательно проверяет экспортированный бинарник в GitHub Actions. Локальные журналы до коммита указывают SHA базового HEAD, а не утверждают, что незакоммиченные изменения уже присутствовали в нём.

GitHub Actions выполняет новые проверки на Linux с графикой и на поставляемом Windows EXE с portable Node. Публикация закрыта, пока эти проверки не прошли; затем проверяются хэши файлов, CRC ZIP и скачивание опубликованного архива по прямой ссылке.
