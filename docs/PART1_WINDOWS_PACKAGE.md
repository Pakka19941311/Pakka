## Состав и запуск

- `RUN_VARENDOR.bat` → `server.ps1` → поставляемый `runtime/node.exe` → `server/launch-world.mjs`. Node/npm на компьютере игрока не требуются; установщик ничего не скачивает.
- `dist/` содержит собранный клиент и локальные игровые ресурсы. Сервер получает тот же `dist/assets/world/world-topology.json`, что вошёл в клиент; упаковщик отвергает расхождение с проверенным исходным файлом карты.
- В ZIP входят только сервер и транзитивные исходные зависимости его импортов. Не нужен `node_modules`; браузерный `src/main.ts` не используется сервером.
- Переносной Node **24.20.0, Windows x64** закреплён в `packaging/windows/node-runtime.json`. Версия и SHA-256 официального ZIP проверены по [списку контрольных сумм Node.js](https://nodejs.org/dist/v24.20.0/SHASUMS256.txt). В поставку включаются `node.exe` и `LICENSE` из этого ZIP. Type stripping поддерживается встроенным Node; см. [официальную документацию](https://nodejs.org/docs/latest-v24.x/api/typescript.html).
- Браузер открывается на прежнем адресе **http://localhost:4173/**. Смена адреса на `127.0.0.1` или другой порт изменила бы область браузерного сохранения. Слушатель сервера при этом ограничен `127.0.0.1`.
- Частная beta явно разрешает однократный перенос старого браузерного сохранения. Существующий серверный валидатор и резервное копирование не обходятся упаковщиком.

Мир сохраняется в `%LOCALAPPDATA%\Varendor\world-beta-v1\world.sqlite`. Извлечение следующего ZIP в новую папку не меняет эту БД. `server.lock` не допускает два процесса с одной БД; после аварийного завершения мёртвый PID распознаётся при следующем запуске. Для копирования резервной копии сначала штатно остановить сервер и скопировать всю папку данных.

Закрытие браузера или окончание входного потока не останавливает сервер. `stop` + Enter и Ctrl+C выполняют штатное сохранение и остановку. Выключение или сон компьютера прекращают работу локального процесса; это не внешний сервер 24/7. Публичное размещение и публичный перенос локальных вещей в поставку не добавлены.

## Точечная проверка подготовки пакета

```sh
node --experimental-strip-types --test tests/world-package.test.mjs
```

Проверяет комплектность серверных импортов реальным запуском подготовленного entry point: независимые от браузера часы, HTML/JS/GLB транспорт, штатную остановку и тот же сохранённый сеанс после смены папки игры. Для проверки транспортного контракта используются маленькие явно тестовые HTML/GLB файлы. Этот тест не считается визуальной проверкой ассетов или нативным Windows запуском.

## Сборка пакета в CI

Предусловия: точный сохранённый SHA, чистый checkout, уже выполненные проверки текущей части; `npm ci`, производственный `npm run build` с `VARENDOR_BETA=1`; Python 3 доступен только на машине сборки.

```sh
node scripts/package-world-windows.mjs --output "$RUNNER_TEMP/varendor-windows" --commit "$GITHUB_SHA"
```

Упаковщик проверяет SHA checkout, чистоту исходников, соответствие карты, SHA официального Node ZIP, комплектность импортов, формирует `BUILD_COMMIT.txt`, `PACKAGE_MANIFEST.json` с размером и SHA-256 каждого файла, проверяет CRC ZIP и записывает `.zip.sha256`. Итоговый JSON сообщает путь, размер, SHA-256 и source commit. По умолчанию результат пишется рядом с checkout, а не в Git. Для повторного использования уже загруженного официального runtime предусмотрен `--node-archive <path>`; проверка закреплённого SHA остаётся обязательной.

Архив: `Varendor_Part1_Windows_Test_<первые 12 знаков SHA>.zip`. Он содержит одноимённую корневую папку. По новому указанию владельца от 07.09.2026 разрешён отдельный промежуточный тест текущего мира без ожидаемых зданий; его нельзя обозначать завершённой частью 1. Workflow `publish-environment-test.yml` подтверждает неизменность проверенного игрового кода, собирает пакет и запускает его на Windows, затем публикует отдельный prerelease. `scripts/publish-environment-test.mjs` проверяет SHA исходников, отчёт Windows, размеры и SHA загруженных файлов и фактическое скачивание публичного ZIP. Перенос generated topology в новый Git-коммит требует обновить source SHA и получить соответствующий клиент перед упаковкой.

## Windows gate для готового ZIP

В отдельном job `windows-latest` получить ZIP без переупаковки. Распаковать в новую папку, затем выполнить из checkout того же SHA:

```powershell
Expand-Archive -LiteralPath $archive -DestinationPath $extracted
$package = Get-ChildItem -LiteralPath $extracted -Directory | Select-Object -First 1
node scripts/windows-world-smoke.mjs $package.FullName
```

На Windows этот smoke запускает именно поставляемый `server.ps1` и `runtime/node.exe`, без подмены установленным CI Node. Проверяет хеши всех файлов, запуск из чужого рабочего каталога, реальные ответы HTML/JS с query/полного GLB, ход серверных часов без клиентов, `stop`, сохранение и восстановление сеанса из той же внешней БД после смены папки игры. Временный `%LOCALAPPDATA%` изолирован от реального пользовательского мира. JSON этого запуска — фактическое свидетельство Windows gate, сохраняется вместе с другими проверками текущей части.

Производственная браузерная проверка игры на этом сервере остаётся отдельным gate части 1; упаковочный smoke её не заменяет. Публикация прямого GitHub Release ZIP разрешена только после всех обязательных gates и проверки удалённого SHA.
