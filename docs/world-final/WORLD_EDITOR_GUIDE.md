# Редактирование текущей географии

Текущий результат — промежуточный этап B, а не завершённый мир. Состояние этапов хранится в корневом `WORLD_STATE.json`.

После чистого checkout выполняется `python scripts/world_final/materialize_payload.py`. Этот же шаг добавлен в существующий GitHub Actions перед импортом. Скрипт восстанавливает настоящие Blender и GLB-файлы и проверяет SHA-256; отличающиеся ручные версии сохраняет и сообщает конфликт.

* Раскладка: `godot-pc/world-final/world_layout.json`. Править ID, позиции, дороги, контуры и маски непосредственно здесь. `initialize_layout.py` повторно существующий файл не заменяет.
* Blender: `art/world-final/Varendor_Geography_final-1.0-layout-06.blend`. Коллекции: рельеф по ячейкам, вода, отдельные ориентиры. Сохранять художественную правку новой версией; не запускать первичный генератор поверх ручной модели.
* Godot: `godot-pc/world-final/geography_preview.tscn`. F1 — обзор, F2 — принятый герой, WASD и ПКМ — существующее управление. Сцена не является заменой основной `main.tscn`.
* Опора: `geography/heightmap.f32`, формат и крайние ячейки описаны в `terrain.json`. Меняя визуальный рельеф, обновлять эту опору из той же сетки и проверять совпадение. Нельзя править только видимую землю, оставляя прежнюю высоту ходьбы.

Скрипты `build_geography.py` и `build_geography_blender.py` используются для начальной географической сборки новой версии. Последний отказывается перезаписывать существующий Blender-master. Изменённые и проверенные экспортированные файлы упаковываются новой версией payload; уже опубликованные части не перезаписываются молча.

Автоматические проверки запуска выполняются через `scripts/godot_run_checked.py`, с новым каталогом результата для каждого запуска. Журнал создаётся до запуска движка. Ошибки импорта и аварийные завершения сохраняются в отчётах независимо от наличия кадров.

Коллизии `geography/collision.json` измерены по настоящим мешам Blender. Мостовые настилы и рампа используют `support-surfaces.json`; наклонная поверхность для камеры проверяется по высоте, а не её сплошному AABB. Обновлять экспорт коллизий после геометрических правок.

Payload schema 2 содержит неизменяемые слои: предыдущие исходники остаются в Git, изменённые файлы дополняют пакет. Автоматически обновляется только файл с известной опубликованной контрольной суммой; неизвестная ручная правка блокирует запись всего набора.
