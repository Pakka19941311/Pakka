# Падение Godot при контрольном запуске — 10 сентября 2026

Упал Godot 4.6.3 при запуске главной сцены без графического окна. Это не импорт, редактор и не экспорт. Консольный запуск завершился кодом **1**; он остаётся неуспешной проверкой. Пользователь сообщил окно процесса `Godot_v4.6.3-stable_win64.exe` с чтением адреса `0x58`. Запускалась его консольная оболочка той же версии.

## Сохранность работы

Ветка `work/character-art-v3`, исходный HEAD `884b26e35508038506fe29477923e08d78744593`. Отслеживаемые файлы на момент проверки не отличались от HEAD. Новые спецификация, раскладка мира и скрипт разметки сохранены. Существующий Blender-мир, GLB и географические данные совпали по SHA-256 с контрольной точкой до падения.

Резервная копия **вне репозитория**, относительно рабочей папки Codex: `outputs/godot-crash-20260910T121037Z/`. В ней 388 файлов, 699 880 959 байт: все неотслеживаемые файлы, затронутые каталоги кода, текущий рыцарь, исходники и анимационные черновики из `work/motion-v3/`, включая `.blend1`. Каждый файл проверен до и после копирования. Предыдущая копия мира: `outputs/world-final-start-20260910-884b26e/`. Откат, удаление или замена игровых ассетов не выполнялись.

## Конкретный запуск и причина

Рабочая папка: `work/Pakka` относительно рабочей папки Codex.

```powershell
& ../tools/Godot_v4.6.3-stable_win64_console.exe --headless --path godot-pc --quit-after 60 --log-file ../qa-artifacts/world-final/baseline-start.log
```

Полные абсолютные пути записаны в `godot-20260910/original-failure.json`. Каталог назначенного журнала не существовал. Перед падением движок сообщил невозможность создать `user://C:`. Баннер запуска и загрузка сцен ещё не появились; файл журнала не был создан.

В [исходнике Godot 4.6.3](https://github.com/godotengine/godot/blob/4.6.3-stable/core/io/logger.cpp#L134) `RotatedFileLogger::rotate_file()` пытается создать каталог через ACCESS_USERDATA и вызывает метод результата `FileAccess::open()` без проверки на null. [Исправление Godot #121926](https://github.com/godotengine/godot/pull/121926) прямо относится к падению при невозможности открыть файл журнала. Вывод нашего запуска, отсутствие каталога и успешный повтор после исправления пути согласуются с этой причиной. Символьной отладки упавшего процесса нет; точный адрес инструкции и сбойный Windows-модуль не установлены.

Это отдельный инцидент от прежнего `git-remote-https.exe`. Доказательств общей причины, переполнения накопителя или неисправности модели рыцаря нет.

## Минимальное обратимое исправление

Добавлен `scripts/godot_run_checked.py`: разрешает абсолютные пути проекта/журнала, заранее создаёт и проверяет запись в точный файл журнала, сохраняет stdout/stderr, команду, cwd, код завершения, время и память дерева процессов. Не перезаписывает предыдущие результаты. Повторяющиеся падающие запуски не выполняет; время работы ограничено.

Исправление касается проверочного запуска. Движок, графический режим, проектные настройки, модель, анимации и системная защита не менялись. Глобальные переменные среды также не менялись.

## Повторные проверки

| Проверка | Результат | Пик рабочего набора Godot | Минимум доступной RAM |
|---|---|---:|---:|
| Минимальный проект, headless-редактор, 60 кадров | Код 0, без аварии, 4,875 с | 675 МиБ | 16,55 ГиБ |
| Текущий проект, исходные 60 кадров | Код 0, без аварии, 3,016 с | 460 МиБ | 16,83 ГиБ |
| Текущий проект, 900 кадров с ограничением 60 FPS для завершения загрузки | Код 0, без аварии, 22,188 с | 1,25 ГиБ | 15,87 ГиБ |

Память измерялась Win32 `GetProcessMemoryInfo` и `GlobalMemoryStatusEx` каждые ~200 мс, включая дочерний Godot, а не только консольную оболочку. Память исходного упавшего запуска не измерялась. Поэтому эти данные подтверждают запас памяти повторных запусков, но не ретроспективный замер исходного процесса.

Журнал приложений Windows доступен. За последние сутки найдена старая запись 1001, **11:08:02 MSK**, `RADAR_PRE_LEAK_64`. Она предшествует исследуемому запуску и не содержит его сбойного модуля/кода исключения. Соответствующая свежая запись Application Error не найдена. `signal 11` не подменяется выдуманным кодом исключения Windows.

Остались отдельные сообщения `Failed to read the root certificate store` и ошибка JSON в чтении пользовательских настроек `interface_polish.gd:33`. При коротком завершении на 60 кадрах были предупреждения об ещё загружаемых ресурсах; при 900 кадрах их нет. Их не называем исправленными и не выдаём код 0 за чистый аудит игры.

Все проверки были **headless**. Они не подтверждают внешний вид мира, плавность анимаций или качество изображения. Мировая задача продолжается с разметки A и построения географии B; готовность мира не заявлена.
