# Копия мира перед обновлением v3

Запускатель проверяет существующую SQLite в режиме чтения до запуска миграций мира. Перед изменением правого слота серьги, прогресса выше 90-го уровня, первого журнала стартовых заданий или схемы P2 он создаёт отдельную копию через SQLite backup API и сравнивает все таблицы и поля состояния. При ошибке копирования запуск останавливается, отметка об успешном обновлении не записывается.

Проверка предметов учитывает сумку, экипировку, добычу, пустые ячейки склада, постоянный резерв миграции и предметы ожидающих наград. Копия сохраняется отдельно от исходной базы. Последующий запуск с теми же версиями и схемой не выполняет миграцию повторно.

Проверено пятью тестами на искусственных SQLite, включая действительный запуск staged `launch-native.mjs`: уровень 100 → 90, сохранение UID правой серьги и кольца на складе, 1151 уникальное существо в P2, сохранение остатка времени убитого босса, повторный запуск и отказ при невозможности создать каталог копии. Таймер босса хранит игровое оставшееся время; закрытая игра его не расходует.

Личное сохранение пользователя в этих проверках не открывалось и не изменялось. Эти проверки подтверждают механизм обновления и серверную часть пакета; они не являются проверкой готового игрового ZIP.
