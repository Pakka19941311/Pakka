# P0-05.3 — Android: сборка проверена, устройство недоступно

Продолжение от `c4a88e841f42a852eb8d8ad098c792a2f19366b4`. **Технический APK успешно экспортирован и проверен; P0-05.3 целиком остаётся blocked**, поскольку физический Android не подключён. P1 не начат.

Использован прежний P0-образец деревянного ящика из Git. Изменены только настройки этого образца: отдельный Android preset, ARM64, отдельное имя пакета, INTERNET, Compatibility renderer на мобильном устройстве и импорт ETC2/ASTC. Это не новый игровой клиент. UID, персонажи, баланс, интерфейс и игровые ассеты не изменены.

## Результат и ограничения

Все **10 условий** runner прошли: Java compile/run, доступность инструментов, экспорт из чистой папки, ZIP CRC, единственный ABI ARM64, ресурсы проекта внутри APK, подпись v2, выравнивание APK на 16 KiB, разрешение INTERNET в манифесте и отдельное имя пакета `org.varendor.p0toolchain`.

APK: **32 445 936 байт**, SHA-256 `7884d266ed063e32655b127f7868641e6e5e75870131c7f77f4f872931eb4ca1`. `minSdkVersion=24`, `targetSdkVersion=36`, см. [badging](evidence/android/apk-badging.log.txt). Это локальный технический артефакт проверки; игровой Release и APK для пользователя не публиковались. В Git сохранены исходники, настройки, воспроизводимая команда, контрольная сумма и журналы. Повторный запуск создаёт новый debug key, поэтому побайтовое совпадение APK и отпечатка сертификата не ожидается.

`adb devices -l` завершился с кодом 0: daemon стартовал, **список устройств пуст**. Установка APK, запуск на телефоне, touch, графический render, FPS и фактическая сеть не проверены. Наличие INTERNET в манифесте не подтверждает соединение. Выравнивание APK само по себе не подтверждает совместимость на реальном устройстве с 16 KiB страницами памяти.

В журнале успешного экспорта остаётся сообщение Godot об отсутствующей иконке приложения; шаблон использует стандартную. Экспорт и последующая проверка подписи завершились с кодом 0. Иконка будущей игры этим образцом не утверждается. Сообщения Godot об отсутствии ADB daemon во время импорта/экспорта также сохранены; позднее отдельная команда ADB запустила daemon и вернула пустой список.

## Первая попытка

[Журнал](evidence/android/first-attempt-android-export.log.txt) и [результат](evidence/android/first-attempt-android-probe.json) сохранены. Первый экспорт остановился на конфигурации, без APK. По [исходнику Godot 4.6.3](https://github.com/godotengine/godot/blob/4.6.3-stable/platform/android/export/export_plugin.cpp) проверка Android проекта требует включённого импорта ETC2/ASTC; он отсутствовал у исходного Linux-образца. Настройка добавлена только в образец P0.

Дополнительно обнаружено расхождение версии SDK: открытое [руководство](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html) указывало 35, а точный template 4.6.3 имеет target 36. SDK 35 в первом журнале выбран как fallback; это предупреждение само по себе не доказывает причину отказа. Успешная попытка использует SDK/Build-Tools 36, без изменения target готового шаблона.

## Воспроизведение

Установить указанные инструменты и соответствующие Android export templates. SDK получен штатным `sdkmanager`; текущие пути среды не являются обязательными. Пример использует переменные с путями к установленным инструментам:

```bash
python scripts/p0-android-probe.py \
  --godot "$VARENDOR_GODOT" \
  --jdk "$VARENDOR_JDK" \
  --sdk "$VARENDOR_ANDROID_SDK" \
  --evidence /tmp/varendor-p0-android-new-evidence
```

Каталог evidence должен быть новым: runner не затирает прежние результаты. Проект и настройки редактора копируются в отдельный временный каталог. Runner не устанавливает APK и не читает пользовательскую базу/профиль. Следующая незакрытая часть P0-05.3 — установка и проверка на доступном физическом Android.
