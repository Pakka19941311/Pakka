Дополнительно найдено по коду/данным, а не доказано самим видео:

- У Bat/Dragon нет Idle: текущий fallback берёт первый attack-клип вместо Flying.
- Завершение старого таймера атаки проверяет только строку `actionType`, поэтому может сбросить более позднюю атаку. Нужен идентификатор конкретной атаки и согласованная отмена.
- До melee impact нет повторной проверки допустимого расстояния; отступившая цель может получить уже визуально неуместный удар.
- Movement audio использует уже созданный пул и cooldown 0,34 с. Сам вызов footstep каждый simulation tick ещё не доказывает создание новых аудиообъектов или причину фриза.
- Обновление секторов/списка теней остаётся заметным в CPU samples. Проверка Babylon показала ранний возврат из `setEnabled` при неизменном значении: ошибочно считать, что сам повторный вызов обязательно перестраивает всё дерево.
- Прыжок, ranged-класс и полный цикл respawn не представлены достаточно явно в записи. Они отдельно проверены в runtime; вывод о них не приписывается видео.
- Выраженного массового проваливания под землю, прежнего наложения панелей и прежнего мерцания дорог в этой записи не подтверждено. Нельзя объявить их регрессией только на основании предыдущего теста.

## Измерение ног и «двойного шага»

На Warrior при игровой высоте 2,05:

| Клип | Полный цикл | Контакты | Оценка скорости опорной фазы |
|---|---:|---|---:|
| Walk | 1,25 с | Одна левая и одна правая опора; окно на границе цикла считается одним | около 1,04 ед./с |
| Run / Run_Weapon | 0,875 с | Одна левая и одна правая опора | около 3,19 ед./с |

Рыцарь перемещается со скоростью 5,89 ед./с: Walk с ratio=1 отличается примерно в 5,7 раза.
Оценка получена по заднему перемещению стопы, пока её Y находится в нижней четверти диапазона;
это калибровка шага, а не гарантия нулевого foot sliding. Левая/правая траектории асимметричны.
В проверке экземпляра проигрывалась одна locomotion-группа. Две нормальные опоры за полный
цикл не являются двойным запуском анимации. Проверка реальных экземпляров подтверждает одну активную группу; неподвижная стопа не продвигает фазу, неизменный gait не вызывает повторный start. Браузерные traces подтверждают отдельное состояние атаки и отсутствие перемещения во время committed melee.

Подробные координаты, длительности и список групп находятся в `clips-baseline.json`.

## Исправления текущего блока

- Единственный контроллер анимации на актор; состояния idle/locomotion/jump/attack/hit/death. Продвижение позы один раз за нарисованный кадр, независимо от числа накопленных simulation ticks. Скрытые акторы останавливают воспроизведение.
- Клип бега и длина шага откалиброваны по поставляемым моделям. Фаза зависит от реально пройденного пути; при упоре в стену не продвигается. Звук шага запускается при пересечении контакта стопы.
- Удалена блокировка разворота 180°. Сохранены скорость и параметры разгона/торможения; визуальный поворот остаётся плавным. Интерполяция отрисованной позиции сглаживает переходы между фиксированными шагами.
- Удалён второй долгий горизонтальный фильтр камеры. Поворот и zoom сглаживаются отдельно; камера проверяет высоту препятствий и поверхность, приближается перед стеной и возвращается на выбранную дистанцию.
- Команда подхода сохраняется до атаки. Удар удерживает позицию, ждёт поворота, имеет windup/contact/recovery. W/A/S/D, прыжок, другая цель и земля отменяют старое намерение; токен атаки предотвращает срабатывание отменённого таймера.
- Melee damage связан с контактом оружия, без дополнительного таймера золотого «снаряда». До контакта повторно проверяется дистанция. Выпущенный снаряд не поражает заново созданный respawn той же сущности.
- Радиусы тел и скользящий контакт не дают герою проходить через моба. Динамические тела не заносятся в статическую сетку навигации. Локальная сетка соседей заменяет полный поиск по всем сущностям при каждом движении моба.
- Статические нетонированные модели используют GPU instances. Анимированные модели, скелеты и тонированные варианты сохраняют независимые клоны; material references и шаблоны не изменяются при удалении экземпляра.
- У Fox нет авторских attack/death clips: добавлено ограниченное процедурное движение корпуса без ходьбы во время укуса и «оживания» трупа. Это ограничение исходного ассета, не новая высококачественная анимация. Bat/Dragon в покое используют Flying.

## Измеренное сравнение

Профиль принятого игрового кода в `752fb581` и исправлений в `b860d29b` на одном GitHub Actions runner.
Chromium / SwiftShader, 1280×720 DPR1, High; адаптация в обоих случаях стабильно 832×468, scale 0,65, detail 2, MSAA 1, shadow map 1024. Настройки между версиями не снижались.
Каждое окно 25–26 с. Это **не FPS игрового ПК**: программный GPU является главным ограничением.

| Сценарий | До avg / max / p95, мс | После avg / max / p95, мс |
|---|---:|---:|
| Idle | 855 / 1100 / 900 | 736 / 817 / 800 |
| W | 976 / 1717 / 1217 | 860 / 1067 / 1050 |
| W → A → D → S + диагональ/ПКМ | 864 / 983 / 950 | 759 / 883 / 817 |

Run: avg −11,9%, max −37,9%. Idle avg −14,0%; direction avg −12,1%.
На этом крайне медленном GPU все измеренные кадры дольше 100 мс; ровные 60 FPS и исчезновение аппаратных микрофризов этим результатом не подтверждены.

Конкретные наблюдения CPU/рендера:

- В W-профиле средние draw calls уменьшились 157 → 135, время анимаций по SceneInstrumentation 3,77 → 1,44 мс. Статические instances уменьшают число отрисовок; один управляемый клип устраняет конфликт состояний.
- Self samples `moveEntityAlongNavigation`: 48 → 15. Удалён полный проход по всем сущностям для поиска соседей; используется локальная сетка. Sample count не является точным временем функции.
- Числа meshes/materials/textures/rigs не показывают пересоздание ресурсов при каждом WASD. В игровых 45 respawn-циклах их количества не растут.
- Переход в движение показывает больше активных meshes/animations и больше draw calls. Прямое движение остаётся дороже idle; назвать эту разницу полностью устранённой нельзя.
- Первоначальный прогон до исправлений имел ошибку стенда: последовательность медленных mouse events растянула C; он исключён из этой таблицы. Приведён исправленный ограниченный по времени парный прогон. 404 favicon устранён на тестовом HTTP-сервере; реальных HTTP/console ошибок в парном прогоне нет.
- Новый герой проходит за 25 секунд стенда больший путь: 68,86 против 55,65 единицы. При software GPU с ограничением catch-up игровой clock не успевает за wall clock; маршруты имеют одну стартовую точку и те же входы, но длины не абсолютно одинаковы.

Последняя небольшая поправка после просмотра кадров: увеличен body radius длинного Fox (включая минибосса) и уточнён контакт Warrior до 50% клипа по реальной траектории Weapon.R. Для неё повторяется игровой gate; таблица относится строго к `b860d29b`, не выдаётся за новый замер финального бинарника. В A/B/C герой не получал урон и не участвовал в боях.

## Ограничения

Software WebGL не заменяет замер на реальном игровом GPU; 60 FPS на компьютере пользователя этим стендом не подтверждаются.
Калибровка шага исправляет крупное рассогласование скорости. Отдельного IK контакта каждой стопы на склонах в этом блоке нет; абсолютно нулевое скольжение не заявляется.
Новые ассеты, графический стиль, классовая математика и следующий блок коммерческого плана не добавлялись.
