## Неподвижные правила

- Не начинаем игру заново. База: `4826f14733e5972784561a1c305a532c9df53e66` из `work/v05-core-quality-rebuild`.
- Работа: `work/v06-commercial-rebuild`. `main` и стабильная v0.5 не изменяются. Никакого force-push.
- Один блок = законченный проверяемый результат, commit в GitHub, Windows ZIP, технический отчёт, пользовательский тест, **СТОП**.
- После сдачи нельзя начинать следующий блок до явного «принято/продолжай» владельца. Замечания исправляются в том же блоке с новой сборкой; прежний ZIP не перезаписывается.
- Технические тесты выполняет разработчик. Пользователь оценивает внешний вид, удовольствие и управление, а не ищет ошибки сборки.
- Статусы: planned → in_progress → technical_validation → awaiting_user_test → accepted. `awaiting_user_test` не означает принятие.
- GitHub Release: prerelease, отдельный tag и SHA; ZIP вне git, проверенные размер, SHA256 и launcher, прямая ссылка GitHub. Сохранения совместимы либо имеют явно проверенную миграцию.
- Коммерческий стиль: **Ashen Gothic Realism** — реалистичные пропорции, суровый средневековый dark fantasy, натуральные материалы, холодный читаемый daylight и тёплые очаги. R2 — только ориентир атмосферы, не источник заимствований.
- Babylon.js/TypeScript сохраняются. Unity не внедряется. Blender — подготовка ключевых ассетов, не автоматическое улучшение качества.
- Никакого auto-play, idle или P2W. Не меняем утверждённые классы, заточку, экономику и PvP-правила без отдельного продуктового решения.
- PC/browser/Windows первыми. Mobile — последующий отдельный профиль той же игры. Ни выход в магазины, ни server-authoritative multiplayer не являются простой упаковкой/переключателем.
- 60 FPS PC Medium 1080p — целевой бюджет на выбранной тестовой конфигурации, не обещание для любого ПК. GPU/CPU/memory/frametime и устройство записываются в отчёт.

## B01 — конкретный выход

1. Снять доступный baseline той же сцены и зафиксировать ограничения стенда.
2. Устранить пропуск игрового времени при длинном кадре; ограничить catch-up при background/resume.
3. Уменьшить частоту presentation-работы и нагрузки AI/navigation, не меняя баланс.
4. Безопасное владение shared textures/materials/rigs при удалении экземпляра.
5. Убрать доказанную избыточность рендера; текущие ассеты до B02.
6. `npm test` → production build (asset verification) → loader/lifecycle checks → **реальный браузер**, управление/screenshots/errors/performance.
7. Windows launcher и ZIP; commit/push/verify remote SHA; prerelease + checksum.
8. `awaiting_user_test`, остановка. Если реальный runtime недоступен, B01 остаётся незавершённым, NullEngine не заменяет его.
