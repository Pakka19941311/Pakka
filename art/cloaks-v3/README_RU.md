# Носимые плащи v3 — рабочая передача

Три отдельных предмета используют авторскую геометрию и собственный риг,
который крепится к уже анимированному верхнему корпусу персонажа.
Серверные характеристики, слот `cloak`, рецепты J и правила добычи не меняются.

## Состав и редактирование

| Предмет | Конструкция | Треугольники GLB | Поверхности |
|---|---|---:|---:|
| `cloak_defense` | Короткая плотная спинка, тонкий тёмный кожаный край, центральная застёжка | 5936 | 5 |
| `cloak_captain` | Длинная выкройка, два крепления, небольшая геральдика трёх башен | 6891 | 5 |
| `cloak_sky` | Два раздельных полотнища, двадцать перьевых деталей, узкий силуэт | 8728 | 6 |

Мастера `Varendor_Cloak_*_Master.blend` содержат отдельные редактируемые детали,
UV, материалы, упакованную фактуру 1024×1024, четыре кости и веса.
Исходные персонажи не включены в эти мастера. В runtime каждый плащ — один
skinned mesh с несколькими материалами. Это фактические размеры геометрии,
а не измеренный выигрыш FPS или обещание автоматического batching.

`build_cloaks.py` воспроизводит геометрию в Blender 4.2.3. После разделителя
`--` принимает `--item=defense`, `--item=captain`, `--item=sky`, `--no-preview`.
`--stage-only` направляет экспорт в локальную папку `staging`, чтобы не менять
runtime во время чужого engine-прогона. Без него экспортируется
`godot-pc/assets/cloaks-v3/`. Повторный запуск заменяет соответствующий мастер;
ручные художественные правки следует сохранять отдельной версией перед запуском
генератора. Не требуется заново экспортировать персонажей.

Происхождение и атрибуция проверочных персонажей: `CREDITS.md`.
`audit_exports.py` читает именно GLB: проверяет нормализацию весов, четыре
действительные кости, внутренние изображения, число мешей и разные координаты
геометрии трёх моделей. Результат хранится в `export-audit.json`.

## Малые интеграционные изменения для владельца world.gd

В этом блоке `world.gd` и `main.gd` не редактируются. Достаточно добавить preload:

```gdscript
const CLOAK_VISUAL = preload("res://scripts/cloak_visual.gd")
```

В цикле игроков `apply_snapshot`, после применения `knight_equipment` и перед
уже существующим обходом `visual` для прозрачности:

```gdscript
if not actor.has_meta("cloak_visual"):
    var accessory: RefCounted = CLOAK_VISUAL.new()
    accessory.bind(actor)
actor.get_meta("cloak_visual").apply_equipment(person.get("equipment", {}))
```

Сразу после `controller.update(motion, rendered_velocity, actor_clock, pose_delta)`:

```gdscript
if actor.has_meta("cloak_visual"):
    actor.get_meta("cloak_visual").tick(actor_clock, motion, rendered_velocity)
```

Время — существующие миллисекунды presentation clock. Модуль сам переводит его
в секунды для слабого колебания; не создаёт отдельный таймер и не использует FPS
как скорость. Нельзя вызывать `tick` до обновления анимации персонажа.

Повторный snapshot и повышение заточки того же плаща сохраняют тот же экземпляр.
Замена освобождает старый узел, снятие удаляет новый плащ. Неподдерживаемый item ID
ничего не подменяет. Оригинальные ресурсы персонажа и общие материалы не меняются.

## Посадка и ограничения

Проверяемые host models: ForgottenKnight, Wizard, Ranger, Rogue и Monk — текущие
представления пяти классов. Godot нормализует имена Mixamo-костей, поэтому
крепление рыцаря ищет суффиксы `Spine2`/`Neck`; у остальных — `Torso`/`Neck`.
Размер вычисляется по реальной высоте шеи в координатах игрового actor, а не по
числовому масштабу исходного GLB. Четырём глубоким торсам Quaternius задана
отдельная глубина спинки и ремней.

Плащ — потомок `visual`: он наследует существующий поворот, прыжок и визуальную
позу смерти. Общий обход MeshInstance для vanish видит его вместе с телом.
Модуль записывает только собственные cloth bones. Они сохраняют исходные
ориентации рига; колебание умножается на них и не сбрасывает их в identity.

У Knight временно скрываются только `FK_chest_cape`, два
`FK_chest_cloak_conector_*` и `FK_chest_top_belt_cloak`. При снятии нового предмета
видимость зависит от действительного текущего `knight_equipment.loadout`.
Снятый за это время нагрудник не должен внезапно вернуть старую накидку.

Нижняя цепь даёт ограниченное кинематическое движение ткани. Это не cloth solver:
на ней нет физических коллизий с телом. При добавлении новых доспехов или клипов
нужна новая визуальная проверка пересечений. У «Крыльев неба» отсутствуют крыловой
размах, полёт, новые столкновения или изменения размеров игрового героя.
При снижении плеч в низкой атаке нижняя цепь подгибается сильнее; высота креплений,
скелет аватара и его координаты не корректируются ради плаща.

## Проверка

Отдельная сцена `res://cloak_visual_acceptance.tscn` использует фактический
`world.make_actor` и текущий animation controller. Она не запускает сервер,
не изменяет сохранение и не имитирует успешное получение предмета игроком.
Опции после `--`: `--cloak-output=<абсолютная папка>` и `--all-cloaks`.
`--no-images` выполняет числовую проверку без снимков. При headless driver снимки
отключаются автоматически: ожидать `frame_post_draw` у Dummy renderer нельзя.
Любой запуск Godot выполняется только через `scripts/godot_run_checked.py`
с новым `--output` и ограниченным `--timeout`, как требует PROJECT_RULES.md.

Проверки включают пять ригов, три действительных skin, отсутствие дубликата при
повторном snapshot, неизменность костей аватара, вычисленную по skin вершинам
высоту над землёй, снятие/смену и восстановление старой накидки. Кадры снимаются
спереди и сзади в idle/run/attack/jump. Числовые PASS не заменяют просмотра кадров:
первый прогон прошёл ground checks, но выявил визуальные пересечения пояса.
Для расчёта вершин QA сначала разрешает непустые имена bind из
[Godot Skin](https://docs.godotengine.org/en/stable/classes/class_skin.html), затем
использует индексный вариант. Проверка только индексного поля именованного skin
может ошибочно вычислить всю одежду по корневой кости.
